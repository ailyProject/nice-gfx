# ChipIntelli CI130X

NICE_GFX 支持 [arduino-ci130x](https://github.com/coloz/arduino-ci130x) 的
`ARDUINO_ARCH_CI13XX` Arduino 平台，包括 CI1302、CI1303、CI1306、
CI-D06GT01D 和 easyVoice 1306 dev 配置。

建议先运行 [CI130X_SSD1306 示例](../examples/01_Basics/CI130X_SSD1306/CI130X_SSD1306.ino)，
使用 128×64 SSD1306 I2C OLED 验证接线、字体和刷新。示例不需要语音资源宏或网络服务。
easyVoice 1306 dev + SSD1306 已完成实板烧录及 I2C/帧写入检查；
2026-11-02 的完整 UI 测试中，用户已确认实屏显示正常、文字清晰。
当前完整 UI 的配置与结果见下方[完整 UI 验证](#完整-ui-验证2026-11-02)。
240×240 彩屏可使用 [CI130X_ST7789 示例](../examples/01_Basics/CI130X_ST7789/README.md)，
其接线、批量传输优化与实板结果见文末的 ST7789 验证。

## 安装与运行

1. 按 arduino-ci130x 的说明安装 **ChipIntelli CI130X Arduino** 开发板包，并选择实际使用的开发板。
2. 安装 NICE_GFX，打开 **01_Basics → CI130X_SSD1306**。
3. 连接 OLED 的电源、GND、SDA 和 SCL；信号电平应匹配开发板。
4. 确认 OLED 的 7 位 I2C 地址；示例使用 `0x3C`，部分模块使用 `0x3D`。
5. 编译、上传，观察计时文本是否每秒更新。

工具链需要完整的 C++ 标准库头文件及目标库，包括 `<atomic>`、`<memory>` 和
`libstdc++`。缺少头文件时请使用 arduino-ci130x 配套的完整 Nuclei GCC 9.2.0 修复包。
Windows 的低内存编译参数及 Arduino IDE 设置见下方[编译回归](#编译回归)。

## I2C 使用固定引脚

CI13XX 的 `Wire` 使用一个硬件 IIC0 控制器，引脚由所选开发板的 variant 决定。
NICE_GFX 的 `I2cWire` 借用已经初始化的总线；应用负责调用并检查
`Wire.begin(SDA, SCL, 100000)`，成功后再调用显示对象的 `begin()`。
不受支持的引脚、时钟和资源冲突由 core 返回 `false`。
推荐使用 Arduino 的 `SDA`、`SCL` 别名，不能套用 ESP32 的任意换脚方式。

| 开发板配置 | SDA | SCL | 共享资源 |
| --- | --- | --- | --- |
| CI1302 / CI1303 | 2 / PA2 | 3 / PA3 | `Serial1` |
| CI1306 / CI-D06GT01D | 15 / PB7 | 16 / PC0 | `Serial1`；部分 PDM 麦克风配置也使用这些引脚 |
| easyVoice 1306 dev | 11 / PB3 | 12 / PB4 | 板载 4.7 kΩ 上拉 |

`Wire` 支持 **10 kHz～400 kHz**，不要使用超出此范围的 I2C 时钟。
当前完整 UI 实测选用 **100 kHz**，作为高频数据 NACK 的配置缓解；允许设置的频率范围
不等于每个频率均已验证稳定。独立的 SSD1306 小示例仍使用 `400000`，其原有 400 kHz
测试记录见下文，不能据此替代完整 UI 的测试。默认 Wire 缓冲区为 64 字节，
NICE_GFX 会分块发送显示数据。

除 easyVoice 1306 dev 自带上拉外，检查模块或外部电路是否有合适的 I2C 上拉电阻。
通用 CI1302/CI1303/CI1306 的 `Serial1` 与 I2C 共用引脚，不应同时启用；
切换功能前先释放相应外设。CI1306 使用 PDM 输入时也需要检查引脚占用。

## SPI 使用软件实现

当前 arduino-ci130x 的 CI13XX 配置没有对外开放通用硬件 SPI。
`SPI` 是 GPIO 软件主机，最高请求频率为 **4 MHz**，实际时钟受指令和中断开销影响。
NICE_GFX 保留 core 的 SPI 初始化、引脚资源声明和事务锁。CI13XX/RISC-V 目标上的
MODE0、无 MISO 写入，在正常 FreeRTOS 任务中自动采用 masked-GPIO 批量快路径；
其他情况使用 core 的批量传输接口。这里没有 DMA、硬件片选或第二个独立硬件 SPI 控制器。
不要将用于启动、模型和用户 Flash 的 QSPI0 改作显示总线。

| 开发板配置 | SCK | MISO | MOSI | SS |
| --- | --- | --- | --- | --- |
| CI1302 / CI1303 / CI1306 / CI-D06GT01D | 5 / PA5 | 2 / PA2 | 4 / PA4 | 3 / PA3 |
| easyVoice 1306 dev | 22 / PD0 | 7 / PA7 | 23 / PD1 | 8 / PB0 |

优先使用 `SCK`、`MISO`、`MOSI` 和 `SS` 别名。软件 SPI 可以选择其他可用 GPIO，
但仍需要避开已被 UART、I2C、PWM、音频等功能占用的引脚。
通用路由的 PA4 在复位时是 `PG_EN` 采样引脚，外围设备不能在芯片复位期间驱动它。
软件 SPI 适合小屏和局部刷新；大面积彩色动画的帧率需要在实际硬件上评估。

## 字体、缓冲区与调度

- SSD1306 示例使用内置 `Fixed6x13` 小字体，不需要外部字体文件或中文字体库。
- 128×64 的 1bpp 像素载荷是 **1,024 字节**；这不是整个应用的 RAM 用量。
  画布、面板缓存、对象、任务栈和语音运行时仍有额外开销。
- RGB565 像素载荷为 `宽 × 高 × 2` 字节，例如 240×240 需要 115,200 字节。
  启用额外画布或双缓冲时，需要再计算对应的占用。
- 字体和图片也会占用用户代码分区。CI1302 的 CWSL 配置可用分区更小，
  应检查所选算法配置的实际编译结果，优先裁剪字库、图片和缓存。
- Arduino `setup()` / `loop()` 运行在原 SDK 的 FreeRTOS 任务中。示例每秒更新一次，
  并在循环中调用 `delay(10)`；避免持续忙等，给系统和语音任务保留运行机会。

## 初始化失败时检查

先检查所选开发板是否与硬件一致、I2C 地址和固定 SDA/SCL 是否正确，
再检查 `Serial1`、PDM、SPI 或其他外设是否已经占用引脚。
保持 I2C 时钟不超过 400 kHz，并检查供电和上拉。
内存不足时先关闭额外缓冲、改用小字体，再根据构建报告缩减静态资源。

## 编译回归

从 NICE_GFX 库根目录运行：

```powershell
npm run test:arduino:ci130x
```

脚本默认编译 CI1302、CI1303、CI1306、CI-D06GT01D 和 easyVoice 1306 dev，
每个板型分别构建 SPI / Sprite / UI 冒烟草图及 SSD1306 示例。草图会先复制到 `.build`，
构建输出也保存在该目录；不会上传固件或执行硬件测试。

可选择 Arduino CLI、配置文件和单个板型，例如：

```powershell
npm run test:arduino:ci130x -- --cli=C:/Tools/arduino-cli.exe --config=D:/Arduino/ci130x/arduino-cli.yaml --fqbn=chipintelli:ci13xx:ci1306
```

`--fqbn` 可用分号分隔多个板型，在 PowerShell 中应给包含分号的整个参数加引号。
额外构建属性通过可重复的 `--build-property=key=value` 传入。
脚本默认 `--jobs=1`，限制 32 位 Windows 编译器处理字体和 UI 时的并行内存用量；
内存充足时可通过 `--jobs=2` 等参数调整。
Windows 下还默认添加 `compiler.cpp.extra_flags=-fno-lto`，避免大字库触发
32 位 GCC 的 LTO 内存限制。自定义此构建属性时，应一并保留所需的 `-fno-lto`。
直接使用 Arduino CLI 编译其它草图时，也可传入
`--jobs=1 --build-property compiler.cpp.extra_flags=-fno-lto`。

Arduino IDE 不会继承回归脚本的参数。Windows 下直接用 IDE 编译时，可在实际使用的
CI130X 平台目录（`platform.txt` 同目录）的 `platform.local.txt` 中设置：
```ini
compiler.cpp.extra_flags=-fno-lto
```
若此属性已有其它选项，应合并保留；重新打开 IDE 后重新编译。
该覆盖文件的放置方式见 [Arduino 平台规范](https://docs.arduino.cc/arduino-cli/platform-specification/#platformlocaltxt)。

若要验证 `D:/Git/chipintelli/arduino-ci130x` 本地源码，先在独立 Arduino CLI 配置中
按该 core 的构建说明接入本地硬件包、匹配的 Nuclei GCC 9.2.0 工具链和 `citool-cli`，
再通过 `--config` 选择该配置。此参数接收 CLI 配置文件，不是 core 仓库目录；
检查构建日志中的平台路径，确认实际使用的是预期源码。以上命令用于复现编译检查，
各板型的其它时钟、麦克风与算法组合仍应按项目配置验证。

## 完整 UI 验证（2026-11-02）

本工作区在 COM23 的 easyVoice CI1306 上，以 SSD1306 128×64、SDA 11、SCL 12、
`0x3C` 和串口 115200 测试完整 Studio 工程。当前硬件测试 harness 默认使用
**100 kHz**，上电自动初始化 **profile 1**；串口采集器另从 profile 0 开始，按
**0、1、1、0（ABBA）** 比较两种配置。profile 0 使用 4 行 tile / 31 B I2C payload，
profile 1 使用 16 行 tile / 63 B payload；各包另含 1 B 控制字节。

Astra 焦点动画的诊断已捕获高频数据包中途的 Wire `3`（data NACK），由
`I2cWire` 映射为 `Status::IoError`，串口显示 `FAIL tick 6`。200 kHz / 0 µs 在第 76 键后
出现 `index=18,len=32`；400 kHz 即使每次成功传输后增加 5 µs，仍在第 27 键后出现
`index=16,len=32`。这些是以 `0x40` 开头的数据包，不能仅用 63 B payload 或包边界解释。
100 kHz / 0 µs 下，Astra 首页两种 profile 各完成 160 次 NEXT/PREVIOUS 焦点按键，
合计 **320 键未记录 BUSERR/FAIL**。当前将降频作为配置缓解，物理根因仍未知，
不能宣称已修复或保证长期稳定。有效对照、早期补充复现与无效初始化记录的区分，见
[总线稳定性诊断及原始证据](../../.build/ci130x-six-20261102/diagnostic/BUS-STABILITY.md)。

本轮完整单色 UI 使用以下局部构建配置：

- `NICE_GFX_UI_MONOCHROME_ONLY` 默认仍为 `0`，保留通用的显示能力判断。
  仅单色部署可显式设为 `1`，使单色路径可在编译期裁剪；checked 创建/挂载接口会拒绝非单色屏。
- 启用 LTO 前，在工作区准备库副本，排除本轮导出未引用的大体积字体编译单元，
  避免 32 位 GCC 处理整套字库时耗尽地址空间。已导出的字体子集和原始库文件保留，
  不能把这份裁剪清单直接用于任意其他工程。
- `-RtosHeapKb 32` 从 SDK 的 AEC 链接脚本生成独立副本，将 RTOS 保留堆设为
  32 KiB，给通用堆留下更多 SRAM。SDK 原始默认的 100 KiB 配置没有改动。
  测试固件还包含禁异常工具链的局部兼容适配；这些内存与运行配置仅验证了本轮 OLED
  界面，不能保证真实语音、音频及其他 SDK 工作负载也能在同一预算下运行。

还需核对启动 loader 的 SRAM 位置。原始主 CPU 镜像从 `0x1FF51000` 加载，
旧嵌入式 loader 位于 `0x1FF9B000`；主 CPU 加载镜像超过 **296 KiB（303,104 B）**
时会覆盖仍在执行的 loader。这里指主 CPU 加载镜像，不是完整 Flash 固件文件的大小。
仅通过链接、compose 或烧录 CRC 校验，不能据此证明大镜像能够启动。

本工作区通过锁定原始 8192 B loader 的 SHA256、核对 34 项重定位修改与最终哈希，
将它移到 `0x1FFC0000`。脚本拒绝未知 loader，并检查应用加载范围；前 8192 B 之后
必须逐字节不变，应用、分区表和资源保持。高址 loader 已用 heartbeat 和完整 UI
验证启动，SDK 全局文件没有修改。该处理只适用于已审计的二进制，不能泛用于任意 SDK。

单项目构建、ROM 握手烧录、上电 profile 1、ABBA 初始化、逐页采集和证据边界，见
[Studio CI130X 硬件测试说明](../../nice_gfx_studio/scripts/ci130x-hardware/README.md)。
OLED 提交帧可核对实际字体和裁切；它们不是光学照片，画面的示例传感器读数也不代表
相应传感器已经接入或通过测试。

## ST7789 240×240 验证（2026-11-02）

COM23 上的 easyVoice CI1306 已完成
[CI130X_ST7789 示例](../examples/01_Basics/CI130X_ST7789/README.md)的目标编译、
烧录、CRC 校验及运行测试。用户已确认实体屏幕显示正常，移动方块没有残留。
该示例使用 RGB565、内置字体和局部绘制，不分配 115,200 B 的全屏 framebuffer。
彩屏编译保持 `NICE_GFX_UI_MONOCHROME_ONLY=0`。

| ST7789 信号 | easyVoice CI1306 引脚 |
| --- | --- |
| VCC / GND | 3.3 V / GND |
| SCL / SCK / CLK | D22 / PD0，板上 SD_SCK |
| SDA / MOSI / DIN | D23 / PD1，板上 SD_MOSI |
| CS | D17 / PC1，板上 SD_CS |
| DC | D16 / PC0 |
| RES / RST | D5 / PA5 |
| BLK / BL | D2 / PA2，HIGH 点亮 |

MISO 不连接；没有 CS 引脚的模块可将示例的 `CI130X_TFT_CS` 设为 `-1`。
SD_SCK/SD_MOSI 的板上标记不改变本 core 使用软件 SPI 的事实。
DC 与 `Serial1` RX、CS 与部分 PDM 路由共用引脚，本例仅启用串口和屏幕。

批量快路径位于 NICE_GFX 库中，默认 `NICE_GFX_CI13XX_FAST_SPI=1`，
其他符合条件的工程重新使用这份库编译即可受益。它在 core 已获取的事务内直接写
GPIO 的 `DATA[mask]`，保持同端口其他引脚；同端口 SCK/MOSI 可合并低相位写入。
每个边沿用低 32 位 `mcycle` 和 SDK 记录的内核时钟重新计时，避免中断后追赶旧
deadline 而缩短相位。批量循环不关闭中断，每 64 B 在 SCK 空闲低电平时协作让出。
请求频率仍限制在 4 MHz，配置频率不代表逻辑分析仪实测时钟。

非 RISC-V 构建、其他 SPI 模式、连接 MISO、ISR、调度器未运行或挂起、周期计数被
禁用等情况回退 core 传输。可用全局 C++ 构建参数
`-DNICE_GFX_CI13XX_FAST_SPI=0` 关闭批量快路径；这个开关只控制 bulk writer，
CS/DC 等 FastPin 信号仍采用当前的 masked GPIO 优化。仅在草图中定义宏不足以
改变单独编译的 `Bus.cpp`，应向整个库传入构建参数。

以下是本轮相同工作量的 MCU 同步绘制耗时；基线关闭批量快路径，双方均使用当前
FastPin、相同请求频率和屏幕配置：

| 工作量 | core bulk 基线 | 优化 bulk | 耗时降低 |
| --- | ---: | ---: | ---: |
| 240×240 全屏填充，57,600 像素 | 536,514 µs | 369,713 µs | 约 31.1% |
| FULL 方块更新，1,152 像素 | 约 11,038 µs | 约 7,668 µs | 约 30.5% |

默认 STRIP 模式只更新前后露出的两条窄带，每步 192 像素，本轮约 1,434 µs。
这是在传输优化之外进一步减少像素工作量，不能把 FULL/STRIP 的时间差写作相同
吞吐工作量下的底层提速。全屏 RGB565 像素载荷仍为 115,200 B，局部刷新与整屏
填充的结果也不能互换为持续屏幕 FPS。

新增 MODE0 主机波形模型已通过 **46,365 项检查**，覆盖 MSB 字节序、双相位最小
等待、32 位回绕、中断延长后不追赶和 64 B 空闲低电平让出；原 Arduino 总线与
DataBridge 行为回归也通过。主机模型检查算法，目标编译、烧录与用户实屏反馈分别
记录，不把无 MISO 的 MCU `status=0` 当作面板读回确认。最终固件与串口证据位于
工作区 `.build/ci130x-st7789-20261102/final-status/`；完整命令和计时口径见示例 README。
