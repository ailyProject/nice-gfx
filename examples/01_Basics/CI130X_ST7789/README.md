# easyVoice CI1306 + ST7789 240×240

独立的 NICE_GFX 彩屏接线与刷新示例。使用内置 `Fixed6x13` 字体，显示七色条、完整屏幕边框、四角位置标记和局部移动方块。没有全屏 framebuffer、Sprite 或外部字体；默认 STRIP 动画只更新移动前后露出的窄条。

## 接线

选择 `chipintelli:ci13xx:easyvoice_1306_dev`。本例数字为该 variant 的 Arduino 引脚编号：

| ST7789 | easyVoice CI1306 |
| --- | --- |
| VCC | 3.3 V |
| GND | GND |
| SCL / SCK / CLK | D22 / PD0，板上 SD_SCK |
| SDA / MOSI / DIN | D23 / PD1，板上 SD_MOSI |
| RES / RST | D5 / PA5 |
| DC | D16 / PC0 |
| CS | D17 / PC1，板上 SD_CS |
| BLK / BL | D2 / PA2，数字 HIGH 点亮 |

MISO 不连接。模块没有 CS 引脚时，把 `Hardware.h` 中 `CI130X_TFT_CS` 设为 `-1`。背光按模块的逻辑控制输入使用；本例没有 PWM 调光。DC 与 `Serial1` RX 共用 PC0，CS 与部分 PDM 路由共用 PC1，本例仅启用运行串口和屏幕。

当前 arduino-ci130x 的 `SPI` 是 **软件 SPI**，请求频率上限为 4 MHz；SD_SCK/SD_MOSI 的板上命名不表示此 core 提供了通用硬件 SPI 或 DMA。本例用 `ST7789_240x240_SPI`；NICE_GFX 的 ArduinoSpi 保留 core 的引脚资源和事务锁，并对符合条件的 CI13XX MODE0、无 MISO、正常任务上下文写入自动启用 masked-GPIO 批量快路径。其他情况使用 core 传输路径。请求速率和 `configuredHz` 均不是逻辑分析仪实测时钟。

做同工作量基线比较时，可对整个库使用全局 C++ 编译参数 `-DNICE_GFX_CI13XX_FAST_SPI=0` 关闭批量快路径；默认值为 `1`。这个开关仅控制批量写入，CS/DC 等 FastPin 信号仍使用 masked GPIO，因此关闭开关得到的是“core bulk writer + 当前 FastPin”的基线。仅在 `.ino` 中定义宏不足以改变单独编译的 `Bus.cpp`，应使用构建属性设置全局编译参数。

## 编译与显示

打开同目录 `.ino`，编译上传；串口使用 **115200、8N1、LF 换行**。彩屏构建保持 `NICE_GFX_UI_MONOCHROME_ONLY=0`；本例会拒绝显式开启单色裁剪的构建。

默认 `CI130X_TFT_SPI_HZ=4000000`，可通过 `Hardware.h` 或编译宏覆盖。例程上电直接显示，先完成一次全屏初始化后才点亮背光。应看到：

- 白色边框四边完整；左上红、右上绿、左下蓝、右下黄，旁有 TL/TR/BL/BR 标记。
- 七条色带从左至右为红、绿、蓝、青、品红、黄、白，用于检查 RGB/BGR 和反色。
- 中部青色方块左右往返，其他区域保持；下方显示运行时间、RUN/PAUSE、STRIP/FULL 模式、累计步数和最近一步绘制时间。

串口 `READY CI130X_ST7789` 表示初始化与静态绘制 API 成功。由于没有 MISO 和面板反馈线，`status=0` 只说明 MCU 提交路径成功；实际方向、颜色、偏移、背光和残影仍需看实屏确认。本例采用库的 `ST7789_Square` 初始化与旋转偏移，分辨率固定为 240×240；其他可视窗口模块应按实际模组调整 PanelOptions，而不是用裁切掩盖偏移。

## 串口命令与计时

| 命令 | 效果 |
| --- | --- |
| `INFO` | 输出尺寸、旋转、引脚、请求/配置速率、模式、每步像素数和状态 |
| `RUN` / `PAUSE` | 启动/暂停移动方块 |
| `FULL` | 两块 24×24 区域重绘，每步提交 1152 像素 |
| `STRIP` | 仅更新离开/进入的两条 4×24 区域，每步 192 像素；上电默认 |
| `REDRAW` | 重绘静态画面并让方块回到左端 |
| `R0` / `R1` / `R2` / `R3` | 选择四种旋转并重绘 |
| `FILL` | 计时一次 240×240 蓝色全屏填充，然后恢复静态示例画面 |

每约一秒输出 `TFT ms=... mode=... stepPixels=... updates=... pixels=... animUs=... maxUpdateUs=... status=... running=...`。`stepPixels` 是当前模式正常一步的像素数，`pixels` 是该窗口的实际动画像素提交总数；RGB565 像素载荷字节数为 `2×pixels`，不含命令和窗口开销。`animUs` 是该窗口内动画更新的 MCU 同步绘制时间总和，`maxUpdateUs` 是最长一步。它们不包含状态文字与串口输出。`ms` 的墙钟窗口包含上一轮状态文字与日志开销，可以用 `1000×updates/ms` 观察此示例窗口内的动画完成速率。

方块宽24像素，每步移动4像素。FULL 清掉旧方块后重画新方块；STRIP 保留重叠的20×24区域，只清离开的4×24带并填入进入的4×24带，像素量从1152降到192，为原来的六分之一。左右往返使用相同规则，边界跨度可被4整除，正常步长保持4。切换模式会先重建当前动画轨道和方块，并清零采样计数，避免残影或在一个窗口混合两种工作量；位置、方向和暂停状态保留。`REDRAW` 或旋转会让方块回到左端，同时保留所选模式。

默认最多请求每 50 ms 更新一次，即约 20 Hz 目标；实际速度受 SPI 与调度限制。不要把这个上限或短窗口计数当作屏幕持续刷新率。比较库批量传输优化时，双方均选择 `FULL`，保持相同命令、采样时长、时钟、方块尺寸和串口输出；FULL/STRIP 的差异属于减少像素提交量的应用层优化，应另外报告，不能当作底层 SPI 在同工作量下的提速。

`FILL` 日志为 `BENCH fillPixels=57600 pixelBytes=115200 us=... status=...`；只计蓝色填充本身，随后恢复静态界面的绘制时间单独排除。115200 B 仅为 RGB565 像素载荷，不包含地址窗口、命令与 CS/DC 切换，也不是整机 RAM 用量。

该示例仅做屏幕显示；没有启用语音、麦克风、Serial1、SD 或其他共用引脚外设。CI130X 通用编译说明见 [CI130X.md](../../../docs/CI130X.md)。
