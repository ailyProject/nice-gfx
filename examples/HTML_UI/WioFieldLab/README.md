# Wio Field Lab / Seeed-inspired UI

Modern v3.1 fixes the SSID list: named results rank ahead of empty names, with RSSI descending within each group. It keeps all complete UTF-8 characters within the 32-byte SSID limit. Empty names appear as `(hidden)` only when fewer than three named results are available. The project adds 49 network-name Han glyphs to its small subset; add other dynamic characters to `fontExport.extraText`, or choose the 3000-character preset after checking the real flash budget. Serial `SSID_ROW` compares the application's formatted result with the native text binding. The v3 design and radar remain in place.

Seven native screens for the actual Seeed Wio Terminal: live light/XYZ dashboard, spirit level, microphone envelope, CSV recorder, NEC infrared transmitter, asynchronous Wi-Fi survey and device settings.

Modern v3 retains the Modern v2 composition following the original modern Seeed visual reference, developed with image generation and Seeed Studio's [branding kit](https://www.seeedstudio.com/blog/branding-kit/) and [design system](https://www.seeedstudio.com/design-system/): deep Seeed Blue #003A4A, cream data cards, Seeed Green #8FC31F, large readings, a central leaf-and-chip hero and six icon launchers. Technical contours and circuit details keep the instrument character. The existing built-in-imagegen hero is a transparent cutout precomposited onto #003A4A for a 112×112 RGB565 resource (25088 bytes). The original official white Seeed Studio logo preserves its aspect and source clear space (128×28, 7168 bytes). Together these embedded bitmaps use 32256 bytes; other graphics, text, charts, focus and controls are native editable UI resources. V3 corrects the radar using native shapes without generating new bitmaps; the v2 design assets and history remain preserved. The current 320×240 editor previews, rather than the historical geek design board, document the implemented layout.

Select `Seeeduino:samd:seeed_wio_terminal` with Seeed SAMD Boards 1.8.6. Install `Seeed Arduino rpcWiFi@1.1.0` (and its dependencies) and `IRremote@4.4.1`. Open WioFieldLab.ino from the Arduino examples menu and upload. The installed NICE_GFX library supplies all display/UI code; no TFT_eSPI dependency or duplicated runtime is included here.

```powershell
arduino-cli compile --fqbn Seeeduino:samd:seeed_wio_terminal --library nice_gfx nice_gfx/examples/HTML_UI/WioFieldLab
```

Five-way directions move focus; top right-hand A opens HOME, B goes BACK, and top left-hand C or five-way PRESS selects. The top legend follows the physical left-to-right order: **C SELECT / B BACK / A HOME**. Buttons debounce and repeat. Keep the display face up for the static level and press ZERO on a reference surface. Light and sound are raw relative ADC measurements, not lux/dB SPL. The accelerometer has no gyro or compass. The board has no touchscreen or battery gauge.

LCD uses SPI3 / SERCOM7, SD uses SPI2, and LIS3DHTR uses Wire1, probing both 0x18 and 0x19 with ID validation. One 320x8 RGB565 drawing tile uses 5120 bytes. Motion includes a floating and breathing hero, a circuit flow point, staggered entry and button feedback, elapsed-time smoothing of the real tilt bubble, and a one-shot chart reveal. The recording lamp is visible only while logging, infrared feedback is finite, and the radio beam appears only while a scan is pending or running. These use no full-screen transition cache, video or bitmap frame sequence. Wi-Fi scan is asynchronous so sensor sampling, CSV recording and navigation continue during the scan. The RPC library starts its FreeRTOS infrastructure before setup.

The Modern v3 radar uses a fixed pivot at screen coordinate **(160,118)**. Its bright beam and five translucent tail sectors each rotate within the same full **120×120** square, advancing **0°→180° in 2200 ms** and repeating. A parent at `x=96,y=58,width=128,height=61` clips the visible upper half. The native shape transform keeps the pivot fixed across drawing tiles; the tail uses five opacity levels rather than bitmap frames. Only a real pending/running scan displays and plays it. Success, failure or timeout hides the sweep and stops its animations. The editable project's PREVIEW action demonstrates the visual effect without a hardware scan.

Insert a supported formatted microSD card and use RETRY SD before recording. Each session creates a new WIO000–999.CSV; existing recordings are not overwritten. STOP flushes and closes the file. A missing card does not disable the live instruments. Infrared commands 0x45/46/47 at address 0x00 are labelled test profiles; change Config.h for your receiver. Config.h also disables optional Wi-Fi/SD/IR dependencies. Settings and zero offsets are held in RAM.

`data/project.gfx-project.json` is the complete editable project, including the RGB565 botanical hero and official logo. Import it into nice_gfx_editor. Hardware application logic lives in FieldLab.h, compiled layout in ui.h. Preserve business element IDs and callbacks when redesigning. The canonical editor source is `nice_gfx_editor/projects/40-wio-field-lab`; `node scripts/export-wio-project.mjs` in that repository regenerates this example plus the standalone Arduino ZIP. Its `design/README.md` and `design/prompts.md` record the visual reference, generated asset and current layout constraints. Official logo source: https://files.seeedstudio.com/wiki/Seeed_Studio_LOGO.zip (PNG/White Logo.png); the Seeed mark belongs to its owner, and this example is not an official Seeed application.

Serial at 115200: 0–6 select routes, n/a/b/c inject logical next/confirm/back/home (`a` injects C SELECT; physical A opens HOME), v reports telemetry and memory including `ui_rev=seeed-modern-v3`. The existing p command captures full-screen RGB888 panel GRAM. New command r captures the 128×61 radar ROI at `(96,58)`: `WIO_RADAR_RLE 128 61 scan=0/1` followed by `[count 1..255, RGB565 high byte, low byte]` triples, ending after 7808 decoded pixels with no trailing marker. These readbacks pause rendering during transfer. The editor repository's `scripts/probe-wio-radar.ps1` and `scripts/check-wio-radar.mjs` save the real scan state, PNGs, beam-tip directions and validation JSON. ROI snapshots cannot verify pixels outside the ROI or uninterrupted frame rate; native host tests separately cover fixed pivot, clipping and tile equivalence. No hardware test result is implied by these instructions. `KEYS` reports actual GPIO edges separately from injected input. Infrared receiver behavior and SD writes require the corresponding external receiver/card for end-to-end checks.
